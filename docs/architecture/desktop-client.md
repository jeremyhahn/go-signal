# Desktop Client Architecture

> **Status: REFERENCE** · Last verified: 2026-10-09
> As-built description of the client-side stack: the Go SDK, the local database, the React frontend, the `desktop` build tag and the web UI served by signald.

## Overview

The client consists of a Go SDK (`sdk/go`), a local embedded database, and a React frontend (`frontend/`). The frontend reaches the Go side in one of two ways, selected at runtime:

- **Desktop**: through Go bindings exposed by the Wails runtime (`WailsAdapter`).
- **Web**: through the REST and WebSocket endpoints that signald serves (`WebAdapter`).

## Local storage

The CLI and the desktop client use the same stack. `sdk/go.NewClient` opens `NewDefaultDAOStore(cfg.DataDir)` unless the caller supplies a `Store`.

```
sdk/go.Client
  |
  sdk/go.DAOStore                (implements sdk/go.Store)
  |
  pkg/daostore.Factory           (15 GenericDAO instances)
  |
  go-qrdb KVStore on PebbleDB
  |
  <dataDir>/pebble/
```

`cmd/signal` defaults `<dataDir>` to `~/.config/signal` (`--config`), and the desktop entry point (`pkg/desktop.RunContext`) uses the same default, creating it with mode `0700`. `sdk/go.FileStore` is the file-based `Store` that the DAO store replaced as the default.

`daostore.Factory` holds one DAO per entity in `pkg/daostore/entities/`:

| DAO | Entity |
|---|---|
| `Messages` | `MessageEntity` |
| `Conversations` | `ConversationEntity` |
| `Contacts` | `ContactEntity` |
| `Groups` | `GroupEntity` |
| `Reactions` | `ReactionEntity` |
| `Attachments` | `AttachmentEntity` |
| `Stickers`, `StickerPacks` | `StickerEntity`, `StickerPackEntity` |
| `Jobs` | `JobEntity` |
| `Sessions`, `PreKeys`, `SignedPreKeys`, `IdentityKeys`, `SenderKeys` | `CryptoSessionEntity`, `PreKeyEntity`, `SignedPreKeyEntity`, `IdentityKeyEntity`, `SenderKeyEntity` |
| `Settings` | `SettingEntity` |

Fields tagged `index:"true"` get secondary indexes. Four entities declare compound indexes:

| Entity | Compound index |
|---|---|
| `MessageEntity` | `ConversationID` + `Timestamp`; `ConversationID` + `IsRead` |
| `ReactionEntity` | unique `MessageID` + `AuthorUUID` |
| `StickerEntity` | `PackID` + `StickerID` |
| `JobEntity` | `QueueType` + `Status` + `NextRunAt` |

`NewDAOStore` panics at construction if `StickerPackEntity.PackID` loses its `index:"true"` tag, because sticker-pack upsert and delete depend on that index.

## Frontend

The React frontend talks to an `ISignalClient` (`frontend/src/sdk/ISignalClient.ts`). `createSignalClient` (`frontend/src/sdk/factory.ts`) returns:

```
React components
  |
  ISignalClient
  |
  +-- WailsAdapter   when window.runtime exists (Wails webview);
  |                  calls the generated wailsjs/go/desktop/App bindings
  +-- WebAdapter     otherwise; calls /api/v1/* on the page origin
                     (or the URL passed in) and listens on /api/v1/events
```

The `wailsjs/` bindings are generated by the Wails build and are not committed, so `WailsAdapter` is only usable in a Wails build.

## Desktop mode

- **Build tag**: `desktop`. It gates `pkg/desktop/**` (`app.go`, `desktop.go`, `bindings/`, `calling/`, `events/`, `jobs/`, `media/`, `ws/`) and `cmd/signal/gui_desktop.go`. Without the tag, `cmd/signal/gui_nodesktop.go` is built instead.
- **Entry**: `cmd/signal/main.go` runs the CLI when it is given subcommands (unless `--gui`), and otherwise calls `desktop.Run(serverURL, dataDir)` through `gui_desktop.go`.
- **Build**: `make build-desktop` builds `./cmd/signal/` with tags `fido2,desktop,codec_json` (plus `qrdb_fts` when `WITH_FTS=1`) to `build/bin/signal-desktop`.
- **Current state of the window**: `desktop.RunContext` creates the app and its embedded store, prints that it initialised, and waits for its context to end. It does not call `wails.Run`. The repository has no Wails module in `go.mod` and no `wails.json`, so `make dev-desktop` (`wails dev`) needs a Wails project that this repository does not contain.

## Web UI mode

- **Served by**: signald, when `frontend.enabled` is true. `internal/frontend` embeds the built assets and signald passes them to the REST server as `FrontendFS`.
- **Client API**: `pkg/api/rest/handlers_webui.go` registers the `/api/v1/*` routes (`account/*`, `messages`, `messages/send`, `conversations`, `contacts`, `call/{offer,answer,ice,hangup}`).
- **Events**: `pkg/api/rest/handlers_webui_events.go` serves `GET /api/v1/events` (WebSocket).
- **SPA routing**: `pkg/api/rest/handlers_frontend.go` is the catch-all at `GET /`, with SPA fallback and cache headers.

See [../api/rest.md](../api/rest.md) for the route table.

## Calling

Calls use the browser's WebRTC stack. go-signal has no Pion or RingRTC dependency.

- **Go**: `pkg/desktop/calling.Manager` tracks call state (`CallIdle`, `CallRinging`, `CallConnected`, `CallEnded`) and call type (audio, video, group audio, group video), and relays offers, answers and ICE candidates (`StartCall`, `AcceptCall`, `EndCall`, `RelayOffer`, `RelayAnswer`, `RelayICECandidate`).
- **Web server**: the `/api/v1/call/*` routes relay signaling.
- **Frontend**: the RTCPeerConnection lifecycle is in `frontend/src/lib/WebRTCManager.ts` and `frontend/src/hooks/useCallManager.ts`; the UI is in `frontend/src/components/Calling/`.

## Make targets

```bash
make build-cli              # signal CLI
make build-desktop          # desktop build of signal
make build-all              # frontend, then signald (web UI embedded) and signal
make dev-desktop            # wails dev (needs a Wails project)
make dev-web                # Vite dev server plus signald
make test-desktop           # tests for ./pkg/desktop/...
```
