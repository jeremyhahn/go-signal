# Plan: Makefile reads GO_BUILD_TAGS (#122)

## Objective

ci-template v1.21+ calls `make lint|build|coverage|security|integration-test
GO_BUILD_TAGS='...'`. The Makefile ignored the variable, so tag-gated code was
never compiled, linted or covered in CI. Every such target must add the
space-separated `GO_BUILD_TAGS` to the tags it already uses; empty changes nothing.

## Slice 1 (one commit)

- `GO_BUILD_TAGS ?=` merged into `BUILD_TAGS` (duplicates dropped), so build,
  vet, lint (`--build-tags`), coverage/test (`-tags`) and gosec (comma form,
  derived from `BUILD_TAGS`) all see it.
- `INTEGRATION_TAGS_FLAG` adds the extras to the `integration` tag in
  `integration-test` and `integration-test-cli`; `integration-test-fido2`
  appends them to its comma list.
- Check: `make -n <target> GO_BUILD_TAGS=zzcheck` prints `zzcheck` in each
  command; `make -n build` without it is unchanged (apart from the build date).

## Slice 2 (review fixes)

- One separator per tag list: `integration-test-fido2` builds its comma list
  with `$(subst $(space),$(comma),...)`, never a mixed "a,b c".
- The Docker path of `integration-test` forwards `GO_BUILD_TAGS` into the
  integration container (`docker compose run -e`).
- `make check-go-build-tags` (test/make/check-go-build-tags.sh) dry-runs the
  integration targets with `GO_BUILD_TAGS='zzone zztwo'` and empty, and asserts
  the exact tag flags.

## Out of scope

Workflows, Go code, the tag set itself.
